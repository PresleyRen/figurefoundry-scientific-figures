# 原生 SVG 示意图和多面板构图

示意图表达对象、关系、步骤或机制；数据图表达测量与分析。两者可以组成一张主图，但每一部分的证据来源应清楚。FigureFoundry 使用普通 SVG 图元和文字生成简明结构图，并将真实 SVG 面板组合成可继续编辑的图件。

复杂科学对象、数学结构或图形摘要可以沿 [optional-backends.md](optional-backends.md) 扩展。本模块不将生成位图当成可编辑示意图，也不会根据装饰图推断实验机制。

## 1. 把科学内容写成实体与关系

先记录主要问题、对象集合、边的含义和不能改动的科学事实。未提供的结构细节可以先保持简化；不能因某种机制“看起来合理”就增添节点、反馈或因果边。

| 概念 | 需要记录的内容 | 示例 |
|---|---|---|
| node / 节点 | 唯一 ID、准确标签、类型、来源 | sample、assay、model、store、result |
| edge / 边 | source、target、方向和关系含义 | 取样、测量、数据传输、更新；不同含义不只靠颜色区别 |
| group / 分组 | 边界及所属对象 | 实验端、分析端；设备内外、训练与推理 |
| constraint / 约束 | 数值、数量、比例、顺序、拓扑、不可变组件 | 同一样本不可画成两个独立队列；训练与测试不能互流 |
| geometry / 几何 | 物理页面与布局位置 | mm 宽高、节点间距、连接端点 |
| evidence_status | 数据、文献、用户描述、假设或教学示例 | schematic；not to scale；synthetic example |

这是构图检查表；实际 JSON schema 以 examples/diagram.json 和脚本帮助为准。不要因为表里出现了概念字段，就假定 CLI 会自动验证其科学真实性。

## 2. 五类常用结构

| 原型 | 主要表达 | 设计要点 |
|---|---|---|
| 实验流程 | 输入、处理、测量、分析、输出 | 时间或因果方向保持一致；并行实验明确分支，样本/数量要对得上 |
| 方法架构 | 模块与数据通路 | 输入输出、训练/推理分界、可学习与固定部分分清；箭头要有语义 |
| 机制示意 | 物质/信号/作用与结果 | 不混淆激活、抑制、运输与相关；缺少来源的箭头不能补成因果事实 |
| 反馈更新 | 状态随证据改变 | 写清更新对象、触发信号、更新操作、频率和接受/拒绝条件 |
| 整体与局部 | 同一结构的概览、剖面或细节 | 局部来自同一对象；保持实体 ID、配色、接口、方向和层序对应 |

反馈环路示例：有持久状态的模型/策略读取数据，评价结果产生更新信号，更新器改变特定状态后继续迭代。记录哪些状态可变、哪些数据/规则冻结、更新多久进行一次，以及失败后如何处理。单独画一条绕回去的圆箭头不会自动解释这些机制。

## 3. 先看灰度骨架，再赋予颜色

先确定阅读顺序、主体大小和文字位置，确保不靠色彩也能跟踪主要关系。颜色代表稳定语义，例如所有图中同一实验组或同一模块类型保持一致；强调色只用于当前最重要的对象，不把不同概念统一染色制造相似性。

用简短标签、合理换行和足够间距降低拥挤。线宽、箭头头部、边界和字号随最终尺寸一起检查。长标签先拆行或缩短术语并在图注解释，不能不停缩字。若增加图标没有提高对象可识别性，就用准确文字。

为需要方向的边画清楚箭头；为表示抑制、约束或无向关联的边选择不同符号并说明。避开边穿过文字、端点悬空、箭头指到框内错误位置、线条误连等问题。颜色与排版不应改变真实拓扑。

## 4. 图元和文字怎么保留

基础几何使用 rect、circle/ellipse、line、polyline、polygon、path 等原生元素，标签使用 text/tspan。节点、边和面板有稳定的分组/ID，有助于定位和扩展。path 可以正常表示箭头或曲线；只有把文字变成纯轮廓才失去直接文字编辑能力。

避免 PNG 嵌入、foreignObject 富文本、外部字体/图片链接和需要滤镜才能阅读的效果。视图清晰、字符保留和科学来源是三个不同检查项，缺一项都不能被另一项替代。

在仓库根目录运行示例：

```bash
python skills/figurefoundry/scripts/figurefoundry.py diagram --spec examples/diagram.json --out examples/outputs/diagram.svg
python skills/figurefoundry/scripts/figurefoundry.py audit examples/outputs/diagram.svg --min-font-pt 6
```

审核后查看实际 SVG/预览，检查坐标、字体、节点边界和科学叙述；不能只看文件非空。

## 5. 把真实数据面板接入组合图

每个数据面板先独立从真实输入生成并审核，再组合。母图分配物理页面宽高与面板矩形；嵌入子 SVG 的图元，保持其文字、坐标、裁剪和引用。不同源图可能使用相同的 ID，需要在组合时隔离命名并重写相应内部引用。

```bash
python skills/figurefoundry/scripts/figurefoundry.py compose --spec examples/composition.json --out examples/outputs/composition.svg
python skills/figurefoundry/scripts/figurefoundry.py audit examples/outputs/composition.svg --min-font-pt 6
```

先做数据面板，再做母图排版，避免把整图 PNG 放入所谓“SVG 容器”。缩放面板后复查实际字号：原先 8 pt 的标签如果缩到 60% 就只剩 4.8 pt。面板字母的位置与大小应统一，但没有科学理由不强制所有面板等面积。

定量区不能保留 DATA HERE 等占位文字后宣称实验图完成。布局草案、合成教程或模板可保留明确的示例标注，正式结果则需要对应真实数据文件、绘图配置和图注。

## 6. 修改与验证

用户要求“配色更稳重”“箭头更细”“标签放大”“整图更紧凑”时，修改相关样式或布局参数并重新生成。要求改变科学关系时，以新提供的事实更新节点/边及来源；不能把科学变化混在一次视觉润色中。

| 检查层 | 可观察证据 |
|---|---|
| 科学内容 | 节点、边、方向、数量与来源一致；示意/假设/测量状态明确 |
| 几何布局 | 无明显遮挡、错连或越界；整体与局部对应；最终宽度下可读 |
| SVG 技术 | 图元和文字存在；无位图包装；内部引用有效；尺寸、缩放后字号符合合同 |
| 多面板语义 | 字母与图注一致，同组同色，同量同单位，比较范围可比 |
| 可重复修改 | spec、数据、生成命令、版本和审核记录齐全 |

自动检查可能发现缺失 ID 或无效引用，却不能判断一条生物通路是否真实；人工预览能发现拥挤，却不能证明数据来源正确。记录每一种实际执行的检查和仍需作者核对的内容，继续保持可编辑源文件。
